# Second-Mac installation pilot

This is the procedure for an authorized teammate pilot, not a claim that a teammate installation has passed. The 0.3 candidate has no redistributed media bundle yet. Clear the scenery/music rights and supply a separately accessible approved library before sharing the complete production system. Times New Roman Regular remains an installed local requirement.

1. Obtain the private release kit and release-manifest SHA-256 from the maintainer through authenticated private access. Check the downloaded manifest and archives against that trusted descriptor. Extract the kit into an owned local folder. Its bootstrap plugin is local source; it is not yet installed in Codex.
2. Have Node/npm, FFmpeg/ffprobe, Python with Pillow, Apple Swift command-line tools and a compatible existing render browser available. Check the exact Times New Roman Regular TTF. Run bootstrap scripts/cli.mjs doctor; resolve missing prerequisites explicitly. No dependency command installs global tools, a browser or system fonts.
3. Run bootstrap scripts/cli.mjs init with the Mac's IANA timezone. Default state is ~/Library/Application Support/Instagram Ads and data ~/Documents/Instagram Ads. The kit path is never the writable campaign root. Use --state-root consistently if choosing a different location.
4. Run release-check and release-stage with absolute --manifest, trusted --manifest-sha256 and local --asset-root. Media is imported and checked independently. Do not use --local-only-assets to redistribute uncleared files. The stage result gives the immutable release ID and marketplaceRoot.
5. Run release-install-dependencies --release-id ID. It installs the retained engine lock in its own version directory. npm registry access may be needed for first setup; future rendering uses local packages/assets and does not require the maintainer's Mac. Register/install the staged/private Git marketplace through the supported Codex client only when authorized. The manager never registers it.
6. Create runtime JSON `{ "version": 1, "browserExecutable": "/absolute/path/to/browser", "serifFontFile": "/absolute/path/to/Times New Roman.ttf", "concurrency": 2 }`. Run release-activate --release-id ID --runtime ABS. Run release-status from the **installed setup skill**; confirm workflow hash match and actual native visualize availability. Source-checkout diagnostics alone do not establish installed readiness.
7. In the local Codex Workspace, submit synthetic Markdown first. Confirm exact source audit and actual inline form, instant settings/music-off/overrides, then final Start production. Verify no intermediate click renders. Inspect dense representative stills/motion/audio, continue the full campaign and verify complete local delivery ZIP/contact/inspection sheets and canonical checksums.
8. Interrupt a synthetic job, close/reopen the client or reboot, inspect recorded process status and explicitly resume only after its worker/renderer exits. Retain already verified outputs. Check update/skipped-version/rollback while another synthetic job is active; its pinned tuple must not change. Never patch its worker snapshot.
9. Authenticate Google Drive with the teammate's own account/plugin, supply an accessible Doc with multiple relevant tabs, verify complete original structured/text snapshots and source audit, and repeat the complete inline workflow. Markdown-only success does not establish Drive success.
10. Record actual Mac model/architecture/macOS, Node/npm/tools/fonts/browser, Codex build/account/workspace/visualize/Drive availability, release/component hashes, installed skill hash, final callback and every delivery/recovery/refresh result. Repeat with the maintainer's Mac offline. Do not declare ready until both the full delivery and preservation checks pass.

For updates, acquire a trusted new manifest, run read-only release-check, stage separately, install packages only for new engines, activate explicitly, and refresh the plugin locally when its workflow changes. Skipped updates leave the current tuple selected. Rollback names a retained old release and probes it again; refresh its plugin separately if necessary. Local campaigns, outputs, jobs and old components are retained throughout.

Use [private releases](PRIVATE-RELEASES.md) for the contract, command details and migration limits. Platform refresh instructions are based on [OpenAI's current packaging documentation](https://developers.openai.com/plugins/build/plugins); the pilot verifies the actual client's behavior.
