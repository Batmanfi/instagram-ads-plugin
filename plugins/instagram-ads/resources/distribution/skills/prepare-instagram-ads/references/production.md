# Local jobs, actual QA and complete delivery

A real final payload has kind instagram-ad-campaign-setup, version 1, demo false and action start-production. Save the complete submitted JSON under the owned workspace. Invoke `node <plugin-root>/scripts/cli.mjs start --state-root <state> --campaign <slug> --chat-id <trusted-id> --choices <submitted-json>`. Use the trusted invocation association, not the payload as authority. Never invoke start from widget state or an intermediate control. Compatibility and older settings-only workflows reject it. Development fixtures additionally require an explicitly authorized --synthetic-qa; do not mark customer campaigns synthetic.

Start validates source/copy/audit/metadata/snapshot, request/order/count, submitted choices, saved per-ad controls, engine/assets and workflow. It freezes the exact submitted bytes and input hashes in a stable job. Repeated semantically identical submissions reuse that job; conflicting settings reject. It launches the densest ad first in a local detached worker. State is durable outside plugin code. The stored job pins engine and asset hashes, browser executable, installed serif hash and a complete workflow snapshot including worker/packager. New local engine defaults do not redirect old jobs.

Inspect `job-status` with the same state/campaign/chat options. Poll with reasonable spacing; it returns progress, worker/render process status, pinned versions and qaBindings. Each attempt's log, runtime, resolved props, report and stills remains under the returned job directory. Ignore overwritten latest-report as whole-campaign evidence. The worker can outlive the conversation; launching is not completion. Do not kill unrelated processes or recover a lock whose owner still exists. PID reuse conservatively blocks recovery and requires inspection.

At awaiting-representative-qa, inspect frames 0, 150 and 299 against source; inspect motion/playback throughout the 10-second clip. Verify exact copy/formatting, phrase wraps, role-specific saved highlights/font/tracking (Style 4 plain serif hook and exact installed Times), emoji, contrast, proportional crop, safe margins, compact grouping and CTA placement. Confirm explicit music selection, gain/cue/fades or silence and the muted scenic source. Every block stays visible for 300 frames. The engine measures after fonts load and fails visibly for invalid copy fit; never rewrite/drop/shrink below 44 px. Automatic grouping uses preferred 64 px/minimum 28 px gaps and center 151.26 px above midpoint, clamped to saved margins. Record necessary layout work separately; frozen jobs cannot silently change source/settings. Fixes to a frozen input require an explicit new campaign/job with preserved prior records.

Record actual inspections, never fabricated pass flags, in version-1 JSON: jobId, reviewer, ads. Each reviewed ad contains id, binding copied from current qaBindings, frames [0,150,299], motionInspected true, notes explaining actual inspection method/findings, and checks with true exactCopy, wrapping, highlights, emoji, contrast, crop, safeMargins, compactSpacing, motion, audio. For absent emoji/highlights explain not applicable in notes. Invoke qa-review with --review <json>. This is Codex's QA record, not another user approval. A representative review starts remaining ads automatically. Inspect the complete set, then record remaining reviews the same way. Changed output/still/resolved-prop hashes invalidate old reviews.

Resume after interruption with `resume` and the same association. It verifies pinned inputs/code/assets and full-decodes/checksums completed files, reconciles per-ad checkpoints, then renders only missing/invalid ads. A live recorded renderer must finish before recovery; the worker may have died while its child continues. --recover-lock is only for a confirmed exited command owner. Existing canonical outputs are never overwritten or deleted. Engine/assets/browser/font changes block resume until the pinned version is restored; they do not silently change active production.

When all valid ads pass QA, invoke finalize with the same association. It rechecks every output, review binding and selected audio before creating a uniquely named local delivery: numbered descriptive MP4s, labeled complete contact sheet, beginning/middle/end inspection sheets, unchanged source and optional raw Google snapshot, exact copy/layout/setup/audit, all representative/remaining reports, verification/checksums, reusable source ZIP and complete ZIP. Source contains the retained engine, pinned lock, all four styles/design folders, compact module/demo, local Roboto/emoji/license records, verified local media and pinned plugin workflow. node_modules, scratch and system Times New Roman are excluded. Both archives pass integrity/count checks; canonical and delivery MP4 hashes match. The local Index is updated, never the maintainer's Video-Editing index.

Missing/failed ads block complete delivery. Retry recoverable failures; report copy-fit failures by ID. If a failure cannot be resolved within the authorized source/layout constraints, finalize --allow-partial can package verified valid ads and explicit failures, but status remains partial-delivery and complete false. Never describe it as a complete campaign. A partial/complete job is closed; a new campaign/job handles later corrections. Repeated finalize verifies/reuses the same committed delivery.

Return working local contact-sheet and complete-ZIP links plus delivered/expected counts and any unresolved limitations. This development candidate has local synthetic evidence only; second-Mac installation, live Google Drive authentication and installed Codex refresh/rollback remain separate acceptance tasks; local release staging/activation/rollback are available through setup-instagram-ads.
