# Source preparation and form workflow

`node <plugin-root>/scripts/cli.mjs doctor` is read-only. For configured installations, pass `--state-root <absolute-root>` to every command; otherwise the default is the current user's `Library/Application Support/Instagram Ads`. `init --state-root ... --data-root ... --timezone ...` creates owned settings and a scoped Workspace/AGENTS.md only for an authorized setup request. It does not install dependencies, change Codex settings or register the plugin.

For new Markdown, archive original bytes via `prepare --copy <parsed-json> --source <original-file> --brand <brand> --chat-id <trusted-context-id> --audit <audit-json> --output <absolute-visualization-path>`. The agent parses actual ordered ads into version-1 JSON with stable IDs, optional title/status and blocks containing id/text/optional role.

The independent audit JSON is version 1 and contains `status: passed`, `method: independent-source-word-audit`, SHA-256 of the original source bytes and parsed JSON bytes, `reviewedAdIds` in original order, `reviewedBlockIds` mapping every ad to its exact ordered block IDs, and an empty findings array only after actual review. The CLI validates coverage/hashes, not semantic truth; the agent must perform that review. Keep any explanatory evidence alongside the audit. The source is never executed.

For Google Docs, apply the installed unified Google Drive guidance. Read metadata and every relevant native tab, retain complete original structured response(s), exact extracted text and source URL. Do not use search snippets or a bounded readable-text fetch as complete content. `prepare` also needs `--source-url` and `--snapshot`. Its audit must contain `sourceCompleteness: {status: complete, relevantTabIds: [...]}` after the agent checks completeness. These fields record the audit; they do not prove connector completeness by themselves. If unavailable/incomplete, request an accessible source and preserve the blocked state. Do not edit/share the Doc or copy credentials.

`prepare` returns the actual campaign slug, form path and `contentReference`. Display it through the installed visualize contract, not a browser server. `form --campaign <slug> --chat-id <id> --output <path>` regenerates a pending form. Source and pending release versions remain pinned.

Pass `--output` inside the current chat's explicitly supplied visualization root when it is available. A campaign's archived form or a file in a different development directory can exist on disk while the native conversation rejects its read request. For that error, preserve the campaign/request identity and display a byte-identical fragment staged in the chat's authorized visualization root. A successful filesystem read or standalone browser test does not prove native conversation access.

A settings-only final payload is `kind: instagram-ad-campaign-setup`, `version: 1`, `demo: false`. Save it byte-for-byte as a submission file under the current owned workspace, then invoke `apply --campaign <slug> --chat-id <id> --choices <submitted-json>`. The resolver rejects wrong requests, source hashes/order/count, malformed overrides, invalid music and contradictory selections. Repeated identical apply is idempotent; changed selections/source need a new campaign. `status --campaign <slug> --chat-id <id>` reads its durable state.

Chat identity is a caller-supplied trusted-context association, not a signed host attestation. The UI prompt cannot make arbitrary payloads trustworthy. This alpha checks that the invocation matches the stored association and performs all source/choice validation. apply saves settings without starting a job. A production-enabled final action is handled with start, as described in production.md; do not turn old settings-only submissions into production requests.

Before preparing a production-enabled form, configure the local engine with the setup skill. prepare records whether production was available at that time. The generated final button is Start production only for that recorded mode; otherwise it remains Save campaign settings. Native browser compatibility tests stay harmless.
