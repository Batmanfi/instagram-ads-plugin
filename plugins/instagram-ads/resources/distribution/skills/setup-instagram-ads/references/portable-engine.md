# Configure the separate portable engine

The engine archive retains the single Remotion composition and exact dependency lock, four styles/design references, compact stacker/demo, local Roboto/emoji/license records. It excludes dependencies, scenic/music media, system Times New Roman and customer campaigns. Provide a separately verified local asset bundle. Installing the plugin does not supply any of these prerequisites.

For an authorized setup, unpack into a unique version directory outside writable campaigns/jobs/outputs, install exact dependencies there using npm ci with an owned cache, and supply an existing render browser executable. Supply FFmpeg/ffprobe, Python/Pillow for delivery and macOS Swift for new emoji. Do not install system software, fonts, browsers or register plugins implicitly. The declared Node >=22 minimum and supported Mac architectures still require validation; local development evidence uses Node24/26 and arm64.

A version-1 runtime file for configuration supplies absolute assetRoot, assetManifest, browserExecutable and optional serifFontFile/concurrency (1–16). Legacy standalone synthetic QA additionally uses mode qa, campaignDir/workRoot/outputRoot and a manifest qaOnly true. Run the engine runtime-doctor with that QA runtime and a no-write dry-run before any authorized synthetic render. For real jobs the plugin builds its own mode job runtime bound to a frozen final Start production specification; do not construct an arbitrary job intent from source content.

Invoke `node <plugin-root>/scripts/cli.mjs configure-engine --state-root <state> --engine-root <unique-engine-version-directory> --runtime <runtime-json>`. It verifies the engine-release file/code hashes, exact installed npm package versions, all asset hashes and actual scenery/music durations, local Roboto files, browser executable, optional exact Times New Roman Regular TTF and delivery tools. It installs nothing and changes only local engine defaults for future jobs. Style 4 needs the exact installed Times New Roman Regular, temporarily copied into job scratch and awaited through FontFace. Missing/substituted fonts fail visibly; system font is excluded from reusable archives.

Only prepare production-enabled campaigns after configuration succeeds. Unconfigured forms remain Save campaign settings and never authorize production, including after a later upgrade. Old jobs keep pinned engine/assets/workflow/browser/font hashes; provide their original version to resume them. For verified release staging, update checks, activation/rollback and the separate Codex refresh step, read [release-updates.md](release-updates.md). configure-engine remains an explicit unmanaged selector; it does not install a plugin or manage a release descriptor.
